# Coordination transport and compatibility

The production reducer has an explicit `CreateProductionAsync(ContinuumMcpTransport, ProductionCoordinationDependencies, ...)` path. It requires a genuine authenticated HTTPS session, fresh exact-project inspection, trusted parent-host deployment and key-to-principal evidence, an actual quiescence/clock binding, a mandatory checkpoint store and finite call/clock uncertainty bounds. The original transport-only overload remains `INCOMPLETE` because it supplies none of those host dependencies. Contract fixtures cannot use the production path.

`ContinuumMcpTransport` implements the official Streamable HTTP lease tools. Configuration explicitly maps the approved bare Forge project key to exactly `project:<project>` on the wire. A different resource scope or owner principal refuses before authentication. Acquire and renew validate every echoed scope/resource/run/lease/fence field before projecting the narrower internal DTO. Inspect masks another run of the same principal. Release sends only the lease/run/request UUIDs supported by the server; the server checks that exact current generation. No wire fencing-token parameter or general filesystem/GitHub fencing is claimed.

The supported response-body profile is strict UTF-8 SSE with CR, CRLF or LF line endings, including fragmented CRLF, at most 1 MiB of bytes and 32 complete event blocks. Comments, id/retry framing metadata and empty-data priming do not create a cursor, timer, replay or reconnect. Event type is empty or message; multiline data fields join with LF. Only structurally valid notifications/progress and notifications/message logging rows may precede the required exact same-request-id JSON-RPC result. Server requests (including ping), cancellation/resource/schema-change notifications, unsupported event types, malformed or unterminated messages and exceeded bounds remain refused and invalidate that transport. No ping reply, cancelled-operation interpretation, new RPC, automatic release retry, metadata refresh or session adoption is implemented. This deliberately closed notification grammar is an availability limitation; synthetic HTTP-handler controls do not certify a live server transcript.

The trusted host's deployment evidence binds endpoint, project, actual principal, private canonical credential SHA256, operator issuer, source revision, image, migration and identity-profile evidence digests and explicit validity timestamps. The key digest is joined to the exact loaded service key before initialize, every call and session DELETE. It must come from an independently verified operator key-to-principal mapping, not a worker label or a locally guessed digest. Credentials and their digests remain private. The source version `0.1.0` and tool discovery alone do not prove a source revision, migration or principal. Public health responses do not supply those claims. The evidence has a maximum20-minute initial age/lifetime and a monotonic remaining deadline once admitted; stale evidence stops future dispatch without inventing a refresh.

One operation gate covers HTTP dispatch, complete bounded decoding and identity projection. No mutation is automatically retried, assigned a replacement UUID, redirected, reconnected or sent to another provider. Cancellation, malformed replies and uncertain outcomes retain the adapter's existing reconciliation/quiescence behavior. HTTP source/streams, credentials and independent first dispositions remain bounded and observed; a failed remote session DELETE is not relabelled successful because the local handler closes. Repeated failed disposition stays failed. Lease state is not removed by session DELETE.

The separate `DeliveryForge.Coordination.LiveControls` executable is a Root-admitted, non-publishing UAT host. It has actual exclusive local checkpoint files with flush/readback and a sealed tracked synthetic dispatch/sink lifecycle. It has no process, model, server-administration or GitHub port. It proves an honestly empty owned-child set for these controls, not quiescence of arbitrary workers. It exercises two operator-bound principals,30-second expiry, replay/contention/masking, successor preservation and real adapter renewal loss after an explicit quiescent external lease-loss injection. Its sink must receive no action after authority loss. The executable is not in the normal solution and does not run during ordinary tests.

No live run follows from source presence. General production scheduling/publication, persistent recovery/takeover, actual worker-host quiescence, installation and distributed certification remain separately configured and validated. The local live-control journal refuses restart takeover and does not claim distributed writer authority. Existing fixture writer epochs and takeover strings remain test-only evidence.

`LeaseOwnership.CleanupComplete` remains value5. `Released` still requires durable release proof for every known identity; absence/replacement proof produces the neutral cleanup summary and retains per-lease terminal facts. No persisted fixture format is silently promoted into production ownership.

The source parent integration composes the actual standalone Tool owner with a mandatory configured Continuum parent before real worker dispatch. It maps the parent-generated worker run to a separately generated wire UUID through a flushed version1 binding and selects issue, reader-verified branch, assigned workspace and conservative repository-wide write resource keys. Branch/workspace values use exact SHA256 canonical keys; repository-write deliberately serializes all protected change-map paths. Detached/unverified branches and noncanonical/unsupported footprints refuse before Start. These are bounded source grammar constructors; the wire schema is unchanged. Actual branch/workspace/repository-write acquire/renew/release UAT remains UNRUN and blocked by the unresolved original operator reconciliation; issue-key controls do not prove those new key shapes are accepted by the live server.

Tool parent creation rejects insufficient lifetime from its same already-read pinned evidence before local checkpoint/session bootstrap, then rechecks actual anchored evidence after discovery and before any lifecycle, lease or worker; it does not re-attest evidence, renew timestamps, reset WORK/cleanup or change authentication/services. A terminal session, ambiguous post-entry checkpoint write or unsettled credential constructor remains fail-closed. Held leases may remain unavailable pending server expiry/reconciliation; TTL expiry and missing diagnostic rows do not prove an unresolved operation was unsent or authorize reconnect/replay/adoption. Renewal rows describe bounded invocations (Pending/Returned/Uncertain), not physical-send or server-outcome proof.

`FileCoordinationCheckpointStore` is a separate production local writer. Its version manifest, parent binding and immutable sequence/SHA records use genuine flush and full readback. Original durability and first-close milestones are retained; visible bytes cannot cure an original failed flush. It refuses existing nonempty roots, restart adoption and distributed takeover. This is a source implementation awaiting independent review and actual runtime validation.

The real parent gates actual host Start/Resume, owned task-process birth and publication mutation enrollment. Its finite renewal shares the original Tool clock and cancellation; failure revokes before another effect. Quiescence closes admission and joins actual parent task sets, adapter session calls, original native retirement/group/IO evidence and the coordinator process registry. Observation itself never stands in for worker settlement. Publication uncertainty remains latched even after a local Task later succeeds. Existing production publication and distributed scheduler factories remain unavailable; these gates do not grant their missing authorization. Contract fixtures and the synthetic live-control host do not certify real parent integration.
The existing ProcessControl owns exact root handles and cannot certify descendant groups. Coordinated auxiliary StartTaskProcessAsync therefore refuses before birth; parent quiescence requires an empty auxiliary registry, rather than promoting root exit to group settlement. Primary Codex/Claude/Pi workers use their separately owned duplex Job/cgroup lifetime and actual original retirement proof. Existing uncoordinated core and conformance paths are unchanged by this explicit limitation.
