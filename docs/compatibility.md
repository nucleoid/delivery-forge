# Compatibility and acceptance

The source targets .NET 10 on Linux and Windows and preserves the repository's exact global.json SDK. Contract schema 1.0.0 and worker envelope 2.0.0 are separate. Help/version/capabilities expose this distinction. No macOS claim is made.

Standalone capabilities reports named diagnostic profiles as INCOMPLETE. Live host transports and actual conformance for Codex, Claude Code and Pi are required before an adapter is called supported; OpenClaw is optional. Parent-issued publication objects remain required for genuine PR/merge. Protected review and coverage policy is unchanged.

Required pipeline chain: actual compiler RED of missing seam where applicable; fresh restore with reviewed new lock files; build and all tests; formatting; package/private-data scan; disposable Linux AND Windows install/uninstall/reinstall with actual shim and host discovery; installed live worker plus independent reviewer plus real quality and current-revision publication; recovery/cancellation/unknown outcomes. Every result applies only to its executed source and boundary. CLI fixtures, package checks and local behavioral tests do not certify the complete installed chain.

Codex app-server and Pi RPC ports use exact parent-selected task instructions. Installed runtime support requires actual conformance for the selected image and platform. Linux native commands require an explicitly provisioned creation-owned scope; missing host prerequisites remain INCOMPLETE. Windows process ownership does not certify Linux ownership.

Linux independent Claude review currently returns INCOMPLETE before native observation or review. A process scope and separate file hashes do not prove that the executed image is the exact immutable selected image. This route requires a supported exact-image execution primitive before it can be enabled. No configuration flag or receipt DATA can supply that missing capability.

Windows production independent Claude review currently returns INCOMPLETE before
reviewer settings/CWD/evidence/auth/native observations or prompt dispatch. The
selected CLI's safe mode disables user plugins, CLAUDE.md/memory, output styles
and user status-line customization, but administrator-managed policy still
applies. The exact pinned CLI does not expose an authoritative complete effective
managed-policy/code-effect inspection contract. A local file or registry absence
cannot prove that device/server policy is absent. Enabling requires a supported
contract or a separately explicit owner trust-policy decision; neither a public
DTO nor a configuration flag can fabricate it. Existing source preparation stays
DATA only, and no positive runtime reviewer or golden acceptance is claimed.
No settings, credentials/login, model, services or resource limits are changed.
Development source-review tooling is a separate route with its own authorization.

The immutable review-source profile retains the existing limits: at most 4,096 filesystem entries per admitted census and a complete Git archive, including headers, fitting the selected MaximumEvidenceBytes (at most 16 MiB). Object/archive grouping reduces parent-admission multiplication; it does not enlarge these bounds or certify the complete worker→gate→review chain for an arbitrary repository. Refusal preserves the actual bounded captures and owned namespace for diagnosis.


Protected changed-line coverage independently inspects the current hash-bound PE, portable PDB and captured source and compiler-source bytes. Exact build/context, module, MVID, CodeView GUID/age/stamp, document checksum and admitted source-role joins must agree. Executable bodies require usable nonhidden points, except for a bounded proof of a plain implicit constructor: one exact top-level, nongeneric, nonpartial class declaration with no explicit/primary constructor, base list or initializer, joined to the complete actual IL body containing only the standard immediate-base Object constructor call and optional no-ops. Extra IL, ambiguous declarations and conditional source directives cannot satisfy that proof. Generated names or attributes never establish it. The line policy separates the pinned Coverlet provider line envelope from required policy lines. For each validated PDB span, the provider envelope includes its start/end physical lines; required policy lines contain nontrivia source-token characters intersecting the exact half-open UTF-16 span. Pure comments, blank lines and an exclusive next-line/column1 endpoint do not add policy lines. Literal token contents and punctuation remain token characters. Provider-only rows are validated but cannot earn denominator or hit credit; missing required measurements remain INCOMPLETE and measured zero remains failure. This is a source-token line policy, not proof that every expression or branch executed. Unbound documents, every other opaque/all-hidden body, debugger-hiding metadata and source-authored #line/#pragma checksum directives remain INCOMPLETE or refused. No coverage-attribute exemption is inferred. This is a whole-module supported profile: an unsupported body, span or mapping in an unchanged or generated compiler input also prevents a complete census. Ordinary async and iterator assembly compatibility remains unestablished. Token projection uses one fixed parser, rejects conditional/remapping or unknown directives and syntax errors, and retains the existing whole-context unsupported-body rules. Genuine compiler fixture coverage does not itself establish actual collector or installed producer compatibility: raw and normalized rows must match the exact supported provider profile and build configuration. A state-machine association alone cannot prove that every unattributed opaque body is nonauthored; those bodies remain unsupported.

In compiler-bound mode, each required executable line/context absent from actual measurements is unmeasured, not removed from the independently compiled denominator. A captured declaration-only input with no compiler points does not require a report-file entry; a declaration-only change still has zero measurable executable lines. Raw report DATA retains its conservative file-membership rule because it has no independent executable inventory. Unsupported document checksum algorithms remain INCOMPLETE; malformed or duplicate identities and bound SHA-256 mismatches are refused. Logical, virtual and physical compiler-document roles retain exact admitted spelling; a physical casing variant is conservatively unsupported rather than resolved through aliases. Repeated executions may combine hits only within the same context; every required context must be measured. Zero measurable changed executable lines remains INCOMPLETE, with no automatic N/A or threshold waiver. Public callable metrics retain their existing semantics. Genuine compiler-fixture controls establish only the tested metadata profile; compatibility with full unfiltered Execution, protected baseline and installed golden runs remains a separate unaccepted requirement.
