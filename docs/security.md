# Trust and resource boundaries

An operator-selected config fixes source root/ref, explicit Git, adapter/version, ceiling, expected plan identities and a downward-only budget. Untrusted repository text, issue bodies, replay artifacts and host capability claims are data. Actual issuer-owned APIs alone provide live worker/publication bindings. No model loop, fallback provider, credential discovery, direct agent CLI or remote service is implemented here.

One ToolLifetime captures monotonic original time before config admission. Downward restriction never creates a new original; total is at most1200 seconds, work at most1100 and cleanup at most the earliest once60 clipped by whole. Host tasks and unknown starts are retained rather than disposed or replayed. Cooperative checks are not a hard OS process/container resource guarantee; admitted validation must supply actual two-CPU/four-GiB/no-server owner infrastructure.

Replay retains at most512 contracts and64MiB raw aggregate; individual inputs are bounded and strict, and public outputs reject private paths/credentials. Packaging has separate explicit archive/expanded/count bounds. Complete raw input hashes, reference graphs, immutable ceilings and drift checks remain authoritative. A successful parser or absence of warnings is never quality evidence.
