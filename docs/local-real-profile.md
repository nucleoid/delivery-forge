# Actual installed local-real acceptance

The opt-in `TrustedConfiguration.LocalRealGolden` selection contains only an
`ArtifactRoot`. The existing `implement` command continues to use the actual
standalone owner, independently conformed installed worker, retained immutable
Git preparation, real installed Crap and mutation producers, and the configured
opposite-family native reviewer. No outcome or capability can be supplied in
this selection.

The protected quality policy still requires the exact independently approved
baseline registry. Missing approval or any incomplete/failed gate remains
non-pass and prevents the local-real reviewer/publication phase. An approval
must be for the concrete artifact produced by actual tools; this profile does
not approve or generate one. The original frozen plan and protected evidence
policy must authorize PR; the local profile never raises an implement ceiling.

After genuine review acceptance, the containing owner rechecks the same worker
completion, original parent admission, exact current configuration/profiles,
owner approval, receipt pins and immutable patch. It calls the existing
production `WorkflowTransition` receiver barriers. Test-realm receipts and
public result flags cannot pass those barriers.

Publication is a fixed private in-memory fake with a local durable intent and
readback journal. There is no URL, adapter, remote-target or live-publication
factory parameter. It never calls a GitHub adapter or merge operation. The
receipt explicitly records fake publication, zero remote writes and no
production publication authority. Existing fixture `PublicationService` and
its safety checks are unchanged. The new phase consumes the same original
work/cleanup endpoints and is retained with the worker frame if unresolved.

An actual successful run writes `<ArtifactRoot>/<actual-runId>/local-real-receipt.json`
and actual run-selection DATA in that same directory, and returns
`ACTUAL_LOCAL_REAL_CHAIN_PASSED` with the directory. This certifies that scoped chain;
slice9 scheduling/provisioning, recovery, production publication and whole-issue
certification remain separate and are explicitly false in the chain receipt.
`ScenarioRunner` capability claims still cannot enable its unconfigured
`LocalReal` branch.

The separately selected `InstalledLocalRealGoldenTests` Fact executes the real
previously installed package entry with root-prepared exact package/install,
configuration, rich-plan and Linux profile pins. It requires the actual host
admission and owner baseline, verifies native closure and exact resulting
receipts, and retains the prefix and failures. It is excluded from ordinary
public CI via `Category!=InstalledLocalRealAcceptance`; absence of private
inputs is never counted as a skipped acceptance pass. No actual acceptance has
been run merely by adding this source.

The separately admitted fresh-process recovery Fact uses
`DELIVERY_FORGE_LOCAL_REAL_RECOVERY_FIXTURE` and its `_SHA256` pin, with
`RunDirectory` selecting that actual returned directory after the first original
is independently known closed. It requires a real new installed process to
return `ORIGINAL_OWNER_REQUIRED` and leave the complete stored record hashes
unchanged. It neither replays a worker nor reconciles old native uncertainty.

Use the existing real stop conformance route for same-original stop. A new CLI
process cannot resume an old native owner from saved JSON; that refusal is a
required recovery behavior. Pause/resume capabilities remain unsupported unless
independently conformed, and fixture crash drivers do not certify live recovery.
