# Prepare real historical quality evidence

`delivery-forge quality-baseline --plan RICH_BUNDLE --config TRUSTED_CONFIG`
runs the two existing installed quality gates over an independently selected
clean historical source H0. An AI worker does not have to produce that commit.
The supplied rich plan is freshly imported at its protected base P; P and H0
must be distinct, and actual Git must prove P is an ancestor of H0.

Use the ordinary independently pinned standalone root, actual measured resource
owner and live Continuum parent. The root's existing `WorkerPaths.Worktree`
selects the already prepared H0 checkout. This command never provisions that
checkout, creates a worker writer, starts an agent, or reconstructs a worker
completion from data. The standalone root still checks its installed executable
and profile pins; merely selecting this command does not grant a host capability.

The trusted configuration selects `HistoricalQuality` with exact `HeadCommit`
and `TreeId`, and `Quality` containing the existing `PolicyRelativePath`,
`PolicyIdentity`, external `ArtifactRoot` and two `Gates` selections. Each gate
selects an independently approved, fully pinned **nonfixture** installed profile.
Prepare a new genuine profile against the accepted installation and source;
changing a fixture flag or relabelling a fixture receipt is not admission.
`InstalledQuality`, review, local-real publication, and a registry selection
cannot be mixed into this historical preparation selection.

Policy, producer configuration, SDK selection and lock files must already be
committed at P. H0 contains the real accepted production change under evaluation.
Select the actual repository's project and tests, and retain the full source
closure. Mutation runs its complete `base` scope without state or a targeted
rerun; Crap runs its selected `base` or `all` project scope. The later callable
comparison requires the exact same profile/package/configuration/scope/project
tuple. Changing that tuple needs a new independently reviewed baseline.

Both real gate calls share one original 1200-second whole lifetime, at most
1100 seconds of WORK, the same parent admission and existing complete-file,
capture and native ownership limits. A selected LocalSingle reservation remains
held throughout both gates. Its unprovisioned ticket is released only after the
actual Quality task and native operations have settled, without stopping an
unstarted worker or renewing a clock. Unknown operations retain the original
owners and capacity. Normal finalization then uses the same cleanup allowance.

Each gate independently resolves the policy from P and checks the actual clean
base/head/tree before and after execution. All original reports, current bindings,
gate receipts, bundle members and failures stay in the fresh external artifact
namespace. If both gates pass, `baseline-candidate-DATA.json` references their
real artifacts and the command returns `INCOMPLETE` with
`HISTORICAL_BASELINE_CANDIDATE_UNAPPROVED`. Any non-pass also remains non-pass.

This command does not issue a registry, owner approval, exemptions, accepted
worker/reviewer, production authority or scheduling certification. The six
genuine report/binding/receipt roles and every original artifact must still be
reviewed and bound by the existing protected registry/independent owner approval
contract. Historical P, baseline H0, later registry R and the independently
selected protected main tip retain their distinct ancestry requirements.

The new path's source and lifecycle controls do not constitute actual installed
acceptance. A real Forge repository, protected policy/configuration and P/H0
selection must be prepared and both actual gates run before making that claim.
