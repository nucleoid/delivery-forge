## Current standalone compatibility boundaries

Non-dry-run standalone `implement` requires the explicit approved `LocalSingle`
selection. That owner provisions the new worktree and retains its actual Git
binding. Precreated worker paths and durable markers cannot be adopted. The
executable refuses a missing provisioning policy before constructing a host or
coordination owner. Historical-quality mode does not dispatch a worker and keeps
its separate route.

Every newly constructed standalone execution composition requires a fresh empty
or absent execution store. This includes non-dry-run `pr`, `merge` and
`quality-baseline`; saved journals cannot construct a live owner. Use `pr` or
`merge` with `--dry-run` for the existing immutable-history diagnostics. Existing
in-flight ownership stays retained for its original owner; use a new selected
store for a new run. This restriction does not grant publication or recovery
authority, and raw old stores remain unchanged.

When installed quality is configured, an incomplete or failed protected-quality
comparison prevents independent reviewer dispatch in single-run and batch
routes. The configured reviewer runs only after actual same-frame protected
completion, or through the existing quality-absent route. A successful tool
result label is insufficient. This avoids spending review allowance on a chain
whose protected prerequisites are incomplete; it does not certify the runtime
reviewer or its independence.

Pinned deployment evidence must cover the actual remaining original interval.
Before creating a checkpoint store, the parent restricts the existing original
with its existing `Restrict` operation to the earlier of the evidence's UTC
expiry and its20-minute age endpoint. The1200s whole/1100s WORK values are upper
ceilings; neither evidence nor a timer is renewed, and the original monotonic
start/token remain unchanged. Discovery independently checks its anchored proof
against the same restricted original. Old or expired evidence cannot admit work.
Closing renewal admission cancels the future-delay wait; an entered renewal RPC
keeps the existing original token and must settle before lease disposition.
Historical uncertain renewals still require supported operator reconciliation.

The review-source availability bounds are documented in
[Compatibility and acceptance](compatibility.md):4,096 filesystem entries per
admitted census and the complete archive, including headers, inside the selected
MaximumEvidenceBytes (at most16MiB). These remain admission ceilings, not a promise
that every repository completes under the original time/byte limits.


### Explicit issue17 personal-host runtime trust

The owner may select `Issue17OwnerTrustedPersonalHost-v1` in the independently
pinned installed-host acceptance. This is a scoped trust decision about the
selected personal Windows host's administrator/server-managed configuration,
not evidence that safe mode inspected or disabled that policy. The containing
root must still pass all five exact installed-host conformance cases and match
the installed Tool image. Only that root can bind the selection to its same
original lifetime, exact containing configuration and selected worker/reviewer.
A DTO or flag passed to a port cannot enable the profile.

The selection pins the explicit owner decision and complete selected host input
files (including explicit absence): at most 16 files, 64 KiB each, 1 MiB total.
The actual Codex-home `config.toml` and Claude configuration-directory
`settings.json` must be among them, outside parent/worker/result/review roots.
The existing restrictive Claude user-settings check remains. Repository/ancestor
Codex configuration is unsupported by this host-only selection. Selected input,
root/configuration decision or relevant environment drift revokes the same WORK
admission without renewal. No credential/configuration values are exported.

Known API/provider/endpoint environment overrides refuse before native birth.
Codex must observe its existing ChatGPT account before thread creation and the
actual `openai` provider with a `gpt-` model before the worker turn starts. Claude
must observe its existing first-party subscription and actual `claude-` runtime
model. No model, login, endpoint, settings or service is changed. Unobservable
administrator/server inputs are the explicit owner trust assumption; redacted
protocol metadata is not an exhaustive endpoint attestation. Cooperative selected
file checks do not exclude an arbitrary hostile same-user writer or remote
policy change that the selected CLI does not expose.

Exact selected Windows executable handles remain held through their actual
original native retirement; unknown disposition retains the same owner. Existing
