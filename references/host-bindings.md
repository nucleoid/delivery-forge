# Host adapter boundary

`CodexHostAdapter`, `ClaudeHostAdapter` and `PiHostAdapter` wrap an actual `IHostToolSessionPort` implemented by the embedding host. No guessed CLI endpoint or environment credential is used. The port supplies a fresh versioned capability profile and actual Start/Wait/Control tasks. Profiles contain at most six capability rows. Production dispatch requires actual conformance; fixture realm is always labelled and cannot certify a live host.

The bridge saves every actual task before waiting. Accepted and completed receipts bind request identity, run, adapter/version, runtime run/task, worktree and original base. Control uses only the private binding obtained from actual acceptance. Revoked profiles, foreign receipts and unsupported pause/stop/resume refuse. Synchronous invocation failure, timeout and missing actual return retain the owner frame and unresolved dispatch; saved JSON cannot clear that state.

A parent constructs ExecutionCoordinator with its real RunStore, worktree owner, process owner and the same named control port, then supplies OwnerHostBridge to ToolApplication. Implement mode uses an actual IWorkerAssignmentPort and the same original; `ExecuteOwnedAssignmentAsync` also supports an explicit containing-owner assignment entry. PauseAsync, ResumeRetainedAsync and StopRetainedAsync act through the SAME retained owner frame, actual controls and original clock; a cold separate operation still requires the actual same coordinator and private adapter binding. The ordinary executable intentionally has no ambient parent objects. Adding concrete host-tool transports and proving conformance is required for an installed live profile; the typed interface alone is not that proof.

Conformance must genuinely exercise dispatch/accept, task attribution, completion, pause/stop/resume and observe-unstarted where supported. Preserve real host tool arguments/returns and unknown tasks, exact version, source/runtime artifact identity and current owner store. Codex, Claude and Pi are independently certified; availability on one does not certify another. OpenClaw remains optional. A development reviewer-family exception does not certify the production independent reviewer profile.

Concrete native source ports currently include Codex stable app-server and Pi RPC over the same original-owned duplex process seam. They require explicit immutable parent instructions before process dispatch: normal CLI derives these from the actual freshly reconciled FrozenPlan; an embedding owner may supply an explicit selected step bound to the complete exact request. Canonical worker2 and plan1 identities remain unchanged. The model receives task, acceptance and selected change/step details, with its paths/exclusions/ceiling, and never the private writer token. A taskless envelope cannot dispatch.

Codex and Pi schemas are independent. Pi uses actual get_state session identity plus the echoed prompt command ID, requires prompt disposition started, then agent_settled and idle state. Its earlier agent_end event does not prove completion. No model/provider/auth override is issued. Pi's disposable in-memory session does not reuse a prior agent conversation. Both ports refuse pause/resume support; stop still requires the original native/IO retirement. These are source implementations awaiting actual installed-version/schema and model-access conformance.

The current Linux duplex extension cannot prove descendant group quiescence from root exit and pipe EOF. Its result remains UNKNOWN and cannot complete a live worker. A creation-owned Linux scope and the surviving-child test must be genuinely implemented/validated before both-OS support is accepted. The Windows original Job route has direct genuine process fixture definitions but has not run. Claude's concrete wire transport and the trusted standalone scheduler/resource composition remain required implementation work.
